## 1. Общая информация о проекте

«Дневник питания» — персональное веб-приложение для фиксации приёмов пищи и наблюдения за пищевыми привычками.

Основные задачи:

- записывать, что и когда было съедено;
- отмечать категории еды и сопутствующую активность;
- просматривать и находить прошлые записи;
- наблюдать за изменениями пищевых привычек;
- анализировать частоту и время приёмов пищи;
- сохранять данные и переносить их с помощью резервных копий.

Приложение не предназначено для постановки медицинских диагнозов и не должно выдавать медицинские заключения на основании записей.

Основная платформа: Android, через браузер и установленную PWA.

Язык интерфейса: русский.

## 3. Основная структура приложения

### 3.1. Главный экран

На главном экране находятся:

- заголовок «Дневник питания»;
- круглая кнопка «⋯» в правом верхнем углу — меню разделов (см. 3.5);
- переключатель «Месяц / Год» и график «Динамика» (количество записей);
- поиск и фильтры;
- список «Все записи» (см. 3.3);
- круглая кнопка «+» для добавления записи.

Напоминание о резервной копии: если в дневнике есть записи, а резервная копия не создавалась 7 дней или ни разу, над графиком показывается плашка с кнопками «Создать копию» (сразу скачивает копию) и «Позже» (скрывает напоминание на 3 дня).

Нижней навигации нет. Все дополнительные разделы открываются через меню «⋯».

График «Динамика»:

- отображение за месяц и за год;
- стрелки «‹ ›» рядом с названием листают месяцы (в режиме «Год» — годы): назад до месяца самой ранней записи, вперёд до текущего; кнопка «К текущему» возвращает к текущему периоду; при переключении «Месяц / Год» и перезапуске показывается текущий период;
- справа — число записей за показанный период с правильным окончанием («1 запись», «2 записи», «5 записей»);
- горизонтальная прокрутка месячного графика; прошлый месяц открывается с 1-го числа;
- нажатие на столбик дня (в режиме «Год» — месяца) показывает в списке «Все записи» только записи за этот день или месяц; над списком появляется пометка «Записи за …» с крестиком; повторное нажатие, крестик или переключение «Месяц / Год» снимают отбор;
- при каждом появлении главного экрана месячный график прокручивается к текущей дате (мгновенно, без анимации); у конца месяца дата не может встать к самому левому краю, это ожидаемо;
- годовой график сохраняет отдельный формат отображения.

### 3.2. Экран добавления и редактирования записи

Поля записи:

- дата;
- время;
- описание еды;
- теги еды;
- теги активности;
- количество углеводов (необязательное поле);
- комментарий;
- уровень голода;
- настроение.

Поле «Еда» содержит подсказку: «Какая была еда и какая была порция? Например: 150 г, тарелка, 2 кусочка». Количество или размер порции не является отдельным обязательным полем.

Уровень голода, комментарий и настроение скрыты под кнопкой «Показать все поля».

Уровень голода:

- пять круглых кнопок «1 2 3 4 5» в стиле выбора настроения;
- пояснение: «1 — не очень голоден, а 5 — очень голоден»;
- по умолчанию ничего не выбрано («Не указан»), и в запись уровень не сохраняется;
- повторное нажатие на выбранную цифру отменяет выбор.

Теги в редакторе:

- показываются с иконками;
- отключённые теги не предлагаются для выбора;
- при редактировании старой записи её отключённые теги остаются видимыми и отмеченными.

### 3.3. Список «Все записи»

Отдельного экрана нет: список находится на главном экране под графиком.

Функции:

- поиск по тексту еды, комментариев и тегов;
- фильтрация по периоду;
- фильтрация по тегам еды и активности (с иконками; отключённые теги не показываются);
- просмотр отдельной записи;
- переход к редактированию;
- удаление записи с подтверждением;
- удаление всех записей с подтверждением.

Периоды фильтрации: «Все записи», «Сегодня», «Вчера», «Последние 7 дней», «Последние 30 дней», «Произвольный период». Для произвольного периода по умолчанию подставляется период с 1-го числа текущего месяца по сегодня; кнопка «Сбросить фильтры» возвращает эти даты.

Записи сгруппированы по датам и отображаются с указанием времени.

### 3.4. Аналитика

Вход — через меню «⋯».

Переключатель периода: «Месяц» и «Произвольный период» (без недельного режима).

Блоки:

1. Общая картина.
2. Распределение по времени суток.
3. Категории еды: сначала три категории с наибольшими показателями, остальные раскрываются кнопкой «Показать все» / «Свернуть».
4. Изменения привычек: сравнение с предыдущим равным периодом и, внутри этого блока, «Наблюдения».

Наблюдения:

- показываются, только если за период не меньше 5 записей;
- иначе выводится одна фраза: «Пока недостаточно записей для наблюдений: нужно хотя бы 5 записей за выбранный период.»;
- всегда показываются три: время суток с наибольшим числом записей, число дней с записями, изменение числа записей по сравнению с предыдущим периодом;
- средний уровень голода — по записям с датой от 26 ноября 2026 года (в более старых записях могло стоять автоматически подставленное «3»), если голод указан хотя бы в 3 таких записях;
- самое частое настроение — если настроение указано хотя бы в 3 записях периода.

Основные принципы:

- использовать только реальные сохранённые записи;
- одна запись соответствует одному приёму пищи;
- не считать отсутствие записи доказательством того, что человек ничего не ел (это сказано и в пояснении внизу страницы);
- не делать медицинских выводов;
- не придумывать данные, которых нет в дневнике;
- учитывать только реально выбранные пользователем теги.

Оформление: между блоками заметное расстояние — `gap: 28px` для `.analytics-page`, внутренние отступы карточек — 16 px.

### 3.5. Меню «⋯»

Круглая кнопка с тремя горизонтальными точками в правом верхнем углу, без подписей. По нажатию открывается всплывающее меню:

- Аналитика;
- Управление тегами;
- Резервное копирование;
- Экспорт данных;
- Оформление;
- О приложении.

### 3.6. Управление тегами

Две группы тегов: теги еды и теги активности, до 30 тегов в каждой. Напитки входят в теги еды.

Пользователь может:

- добавлять теги;
- переименовывать (✎): новое название автоматически подставляется во все записи с этим тегом той же группы; в окне переименования показано, сколько записей изменится;
- выбирать иконку;
- отключать (Ⅱ) и включать (✓): отключённый тег не предлагается в новых записях, фильтрах и аналитике, но остаётся в старых записях;
- удалять (×) с подтверждением; если тег есть в записях, подтверждение сообщает, в скольких записях он сохранится;
- менять порядок перетаскиванием за значок с точками (кнопок-стрелок нет).

Пояснение к значкам свёрнуто под заголовком «Подсказка» и раскрывается нажатием.

Раздел «Теги из старых записей» (свёрнут, показывается только при наличии таких тегов): названия тегов, которые есть в записях, но отсутствуют в списке (после удаления, переименования до версии 1.1 или восстановления копии), с числом записей и действиями:

- «Вернуть в список»;
- «Заменить на…» — замена названия в записях на существующий тег после подтверждения.

Записи при этом никогда не удаляются.

Иконки — библиотека lucide-react и несколько собственных значков (помидор, кофейная чашка с зерном, стаканчик смузи с клубникой, метла). Иконки отображаются в управлении тегами, в редакторе записи, в фильтрах, в карточках записей и в аналитике.

### 3.7. Оформление

Светлая, тёмная и системная тема. Выбор сохраняется между запусками. Новые элементы проверяются в обеих темах.

### 3.8. Экспорт данных

Форматы: Excel (.xlsx) и CSV (разделитель «;», кодировка UTF-8 с BOM, каждая запись на отдельной строке).

Периоды: «Все записи», «Текущий месяц», «Последние 7 дней», «Произвольный период» (по умолчанию с 1-го числа текущего месяца по сегодня).

Переключатели включения: теги еды и активности; углеводы и комментарии; уровень голода и настроение.

Надпись под кнопкой зависит от выбранного формата.

Кнопка «Поделиться» (только для CSV) создаёт тот же файл и открывает системное меню «Поделиться» (Web Share API), если браузер это поддерживает. Для Excel кнопки нет: Chrome на Android отказывается делиться файлами .xlsx, хотя `navigator.canShare` для них возвращает true. Для Google Таблиц на телефоне рекомендуется Excel: приложение Google Таблицы на Android не открывает CSV из «Загрузок».

Экспорт не изменяет и не удаляет исходные записи.

### 3.9. Резервное копирование и восстановление

Резервная копия создаётся в формате JSON, имя файла начинается с `food-diary-backup-`, файл скачивается на устройство.

В копию входят: записи дневника; теги еды; теги активности; отключённые теги; иконки тегов; тема оформления.

Восстановление — выбором JSON-файла. Перед заменой текущих данных показывается предупреждение и запрашивается подтверждение. Структура файла проверяется.

Формат копии: `app: "food-diary"`, `version: 1`.

### 3.10. О приложении и иконка

Раздел «О приложении» показывает иконку приложения, описание, сворачиваемые пояснения о хранении данных, резервном копировании и экспорте, а также предупреждение, что приложение не медицинское.

Иконка приложения: светлый блокнот с пружиной и светло-зелёным листиком на зелёном фоне (`#68734b`). Используется на главном экране телефона, во вкладке браузера и в разделе «О приложении». Есть вариант для круглой обрезки (maskable).

## 4. Хранение данных

Данные хранятся только локально, в `localStorage` браузера.

Ключи:

- `food-diary-entries` — записи;
- `food-diary-food-tags`, `food-diary-activity-tags` — списки тегов;
- `food-diary-disabled-food-tags`, `food-diary-disabled-activity-tags` — отключённые теги;
- `food-diary-tag-icons` — выбранные иконки тегов;
- `food-diary-theme` — тема оформления;
- `food-diary-last-backup` — сведения о последней резервной копии;
- `food-diary-backup-reminder-snoozed-until` — до какого момента скрыто напоминание о резервной копии;
- `food-diary-storage-version` — версия формата данных (сейчас `1`);
- `food-diary-icon-update-1` — отметка о разовой замене иконок тегов (ноябрь 2026);
- `food-diary-damaged-<ключ>-<время>` — копии повреждённых данных, если их не удалось прочитать.

Поведение при запуске:

- новый дневник начинается пустым, без демонстрационных записей;
- сохранённые данные читаются безопасно: если значение повреждено или имеет неверную структуру, приложение всё равно открывается, сохраняет копию повреждённого значения и показывает предупреждение на главном экране.

Ограничения:

- данные привязаны к конкретному браузеру и устройству;
- синхронизации между устройствами нет;
- удаление данных браузера может привести к потере записей;
- для переноса и восстановления данных нужна резервная копия.

Любые изменения механизма хранения должны учитывать существующие данные. Нельзя менять структуру записей или ключи хранения без механизма миграции; версию формата повышать в `food-diary-storage-version`.

## 5. Навигация и поведение на Android

Приложение устанавливается как PWA и работает без интернета.

Требования:

- корректная работа в установленном режиме;
- сохранение данных после закрытия приложения;
- корректное обновление опубликованной версии (Service Worker удаляет устаревшие файлы прежних версий из своего кеша);
- работа системной кнопки «Назад».

Кнопка «Назад» возвращает на предыдущий экран, закрывает меню или редактор и не приводит к неожиданному выходу. В истории браузера всегда ровно столько записей приложения, на какую глубину открыт текущий экран:

- главный экран — 0;
- меню над главным экраном, раздел, просмотр записи, новая запись — 1;
- меню над разделом, редактирование существующей записи — 2.

Когда приложение возвращается само (сохранение, удаление, выбор пункта меню, закрытие меню), лишние записи истории убираются, поэтому «пустых» нажатий «Назад» нет. Логику на основе `popstate` не удалять и не заменять без проверки всех сценариев.

## 6. Дизайн и визуальные требования

Общий стиль: спокойный, минималистичный, светлый, с природными зелёными оттенками, без перегруженности, удобный для смартфона.

Принципы: крупные области нажатия; читаемые подписи; аккуратные карточки; единообразные кнопки и иконки; логичные отступы; отсутствие лишних декоративных элементов.

Светлая и тёмная темы согласованы; новые элементы проверяются в обеих.

Не менять утверждённые элементы дизайна по собственной инициативе.

## 7. Согласованные решения, которые необходимо сохранять

1. Название приложения — «Дневник питания».
2. На главном экране не использовать заголовок «Мой дневник».
3. Описание порции — часть подсказки в поле еды, а не отдельное обязательное поле.
4. Напитки относятся к тегам еды.
5. Пользователь самостоятельно управляет тегами и их иконками.
6. Теги переставляются перетаскиванием; кнопок-стрелок нет.
7. В аналитике используются только реальные записи и выбранные теги.
8. Отсутствие записи не означает отсутствие приёма пищи.
9. Аналитика не превращается в медицинскую оценку.
10. Для аналитики используются месячный и произвольный периоды, без недельного режима.
11. Для месячного графика важны горизонтальная прокрутка и положение текущей даты.
12. Резервное копирование и восстановление доступны и понятны.
13. Удаление всех записей всегда требует подтверждения.
14. Системная кнопка «Назад» работает внутри приложения без «пустых» нажатий.
15. Нижней навигации нет; разделы открываются через меню «⋯».

## 8. Правила работы ИИ-разработчика

Пользователь не является программистом. Технические действия объясняются простым русским языком.

Перед изменением кода:

1. Изучить актуальный код в GitHub.
2. Проверить, какие функции уже реализованы.
3. Уточнить, какие файлы затронет изменение.
4. Объяснить, что предлагается изменить и зачем.
5. Указать возможные последствия для других частей приложения.
6. Получить согласие пользователя.

Не просить пользователя вручную копировать файлы или выполнять команды в терминале, если работу можно выполнить через GitHub.

При внесении изменений:

1. Перед редактированием получать актуальную версию файлов.
2. Не перезаписывать новую версию файла старой копией.
3. Вносить минимальные изменения, необходимые для задачи.
4. Не удалять существующий функционал без прямого согласования.
5. Не проводить масштабный рефакторинг попутно с небольшой правкой.
6. Сохранять совместимость с существующими данными в `localStorage`.
7. Делать понятные отдельные коммиты с описанием изменений.
8. Если изменения готовятся в отдельной рабочей ветке, переносить их в `main` (то есть публиковать) только после согласия пользователя.

После изменения кода:

1. Проверить TypeScript и сборку: `npm run build`.
2. При необходимости проверить ESLint: `npm run lint` (известное ложное срабатывание: правило `react-hooks/purity` на `Date.now()` в обработчике сохранения записи).
3. Проверить изменение в браузере, включая соседние функции и обе темы.
4. Проверить GitHub Actions для последнего коммита в `main`.
5. Не сообщать, что приложение опубликовано, пока GitHub Actions не завершился со статусом «success».
6. После публикации сообщить пользователю, что изменилось и что проверить на телефоне.

Общение с пользователем:

- работать пошагово;
- не перегружать длинными инструкциями;
- не использовать сложные термины без пояснения;
- не задавать несколько вопросов одновременно;
- не принимать решений, меняющих поведение приложения, без согласования;
- при обнаружении ошибки объяснить причину и предложить конкретное исправление;
- сначала обсуждать идеи, затем менять код.
